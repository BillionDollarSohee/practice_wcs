# Kata 5 — PLC 읽기 파이프라인 (오후 한 번에 끝내는 분량)

실무 `FEnetPlcInterfaceService` 의 읽기 핵심 3조각을 작게 뽑아 만든 kata 입니다.

| PART | 파일 | 실무 원본 | 한 줄 요약 |
|---|---|---|---|
| A | `WordBit.cs` | OneCakeRead 의 BitArray/워드 계산 | byte[] 에서 워드·비트·문자열 꺼내기 |
| B | `ChunkedReader.cs` | `ReadPlcContinuousChunked` | 한 번에 못 읽는 큰 요청을 쪼개 읽고 이어붙이기 |
| C | `SegmentBuilder.cs` | `BuildOneCakeReadSegments` 앞부분 | 흩어진 읽기 항목을 가까운 것끼리 구간으로 묶기 |
| D | `PlcSnapshot.cs` | OneCakeRead 전체 흐름의 축소판 | A+B+C 합쳐서 "이름 → 값" 만들기 |

`FakePlc.cs`(가짜 PLC)와 `Program.cs`(자동 채점기)는 **수정하지 않습니다.**

## 실행

```
dotnet run                 # 전체 채점
dotnet run -- B            # PART B 만
```

처음엔 전부 `TODO` 로 나옵니다. 하나씩 `PASS` 로 바꿔가면 됩니다.

## 연습 순서 (이게 핵심입니다)

각 PART 마다 아래 4단계를 지킵니다. 건너뛰면 "따라 치기"가 됩니다.

1. **말로 설명** — `NOTES.md` 에 함수별 3줄(입력 / 출력 / 실패·경계)을 먼저 적는다. 코드 금지.
2. **백지에서 구현** — 인터넷·원본 코드 없이 TODO 를 채운다. 막히면 *막힌 위치*를 `NOTES.md` 하단에 기록.
3. **채점** — `dotnet run -- A` 처럼 해당 PART 만. `FAIL` 의 `→` 뒤 메시지를 읽고 *코드를 보지 말고 먼저 이유를 추측*한 뒤 고친다.
4. **원본과 비교** — PART 를 다 통과하면 실무 코드의 같은 함수를 열어서 차이점을 `NOTES.md` 에 적는다.
   (내 방식이 더 나은 곳 / 원본이 이유가 있는 곳 / 그냥 취향 차이)


## 막히면 이 순서로

1. 에러 메시지 / FAIL 메시지 읽기
2. 종이에 구체적인 숫자로 한 번 손으로 돌려보기 (예: `ReadChunked("D", 0, 2500)` 의 루프 3바퀴 각 변수 값 적기)
3. 힌트(TODO 주석) 다시 읽기
4. 그래도 안 되면 **시도한 코드를 가져오기** — 정답 대신 "어디서 왜 틀렸는지"만 짚어드립니다.

## 다 끝나면 (다음 단계 예고)

- **버그 심기 드릴**: 완성한 코드에 제가 버그 1개를 심어서 드립니다. 실행하지 않고 읽기만으로 찾는 연습입니다.
